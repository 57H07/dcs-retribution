# Web UI: what is already on `dev` (for sub-agents)

Read with `implementation-brief.md`. Updated by the orchestrator as lots land.

- **Client:** Vite 8, TS 5.9, Vitest (`npm test` runs once), React 18, RTK Query generated offline (`python -m game.server.openapischema` then `npm run regenerate-api`).
- **Design system:** `client/src/ui/` (tokens `--ui-*`, Radix-based components, `MilSymbol`, `TaskTag`, `Menu`, `Toast`, …). Dev catalog: `client/catalog.html`. Add a component there only if it is generic.
- **Shell:** `client/src/shell/` — hash router (`routes.tsx`, `paths.ts`), `AppBar.tsx` = full top bar (WEB-01.1), menus `appMenus`, shortcuts (`shortcuts.ts`; layer toggles via `client/src/maplayers/layerToggle.ts` `toggleOverlay()`), `QtScreen.tsx` fallback that opens a Qt dialog through `POST /qt/dialogs/{dialog}`.
- **Command view (WEB-01 done):** `client/src/command/` — `CommandView.tsx`; packages panel `command/packages/` (`GET/POST/DELETE /packages`, stable `Package.id`); map layer toolbar `components/layertoolbar/`, dark basemap, inspector `command/inspector/MapInspector.tsx` (`GET /control-points/{id}/summary`, `/tgos/{id}/summary`; base actions go to `/bases/:id`); timeline `command/MissionTimeline.tsx` (`GET /game/timeline`); shared package selection `client/src/api/selectionSlice.ts` keyed by `Package.id`; `TurnActions.tsx`; `useTakeOff.ts` (`POST /game/mission` → `/waiting`).
- **Mission result (WEB-05 done):** `/waiting` and `/debrief` (`client/src/missionresult/`); engine `game/commands/missionresult.py`, report `game/debriefingreport.py`, routes `game/server/missionresult/` (`GET /game/mission/result[/report]`, `POST .../file|cancel|accept`).
- **Base screen (WEB-02.1, 02.2):** `/bases/:id/:tab` (`client/src/bases/`, `GET /control-points/{id}/base`, repairs `game/commands/repairs.py`, aircraft orders and squadron creation `game/commands/aircraftorders.py`, `AirfieldTab.tsx`, `Tags.BASE`). Ground forces, convoys and base radios: `GroundForcesTab`, `game/commands/{groundorders,frontline,baseradios,cheats}.py` (WEB-02.3).
- **Reports and secondary screens (WEB-08.1, 08.2):** `/reports/:tab` (`client/src/reports/`), `/transfers`, `/notes`, `/info`, `/career`, `/logs`, `/about` (`client/src/secondary/`). Site and unit sheets: `/tgos/:id`, `/units/:kind/:name` (`client/src/tgos/`, `game/commands/groundobjects.py`).
- **Air Wing (WEB-03):** `/air-wing` (`client/src/airwing/`, `game/commands/squadrons.py`, `game/server/airwing/`). `QtDialog` and `POST /qt/dialogs/{dialog}` are gone; `QtScreen` remains for `/new-game` only once WEB-04 lands.
- **Package editor (WEB-04.1):** `/packages/:id` (`client/src/packages/`, tab frame `FlightSections.tsx`, `game/commands/packageflights.py`); each flight tab has a temporary "Open the Qt editor" button.
- **Ground object and unit sheets (WEB-08.3):** `/tgos/:id` (`client/src/tgos/`, `GET /tgos/{id}/sheet`, rules in `game/commands/groundobjects.py`, `Tags.TGO`), `/units/:kind/:name` (`PATHS.unit(kind, variantId)`, `GET /unit-info`, `/unit-info/banner`): link there from any unit list. `POST /qt/info/tgo/{id}` answers 503 in web mode.
- **Flight-plan regression (WEB-04.0):** `tests/flightplans/` (README lists what WEB-04.1-04.3 must reproduce; refresh with `UPDATE_FLIGHTPLAN_FINGERPRINTS=1` only for an intended change).
- **Server:** every route `@locked` (`game/gamelock.py`, enforced by a test; native dialog routes use `@locks_game_itself`); business logic in `game/commands/`; errors `CommandError` → 409; API key `X-API-Key` on non-GET, `?apiKey=` on `/eventstream`; Qt notifications through `QtCallbacks` (`game/server/dependencies.py`) emitting queued signals on `QLiberationWindow`.
- **Existing web screens:** `/settings` (`client/src/settings/`, `game/server/gamesettings/`), `/preferences` + first start (`client/src/preferences/`, `game/server/preferences/`; install prefs now in `game/liberation_install.py`), top bar data `GET /game/top-bar`, native bridge `/native/*` incl. `pick-folder` (`game/native/`, `qt_ui/nativebridge.py`).
- **Guide:** `docs/dev/api-commands.md` (§1-§9). Keep it updated when you add a pattern.
- **Transition rule:** the web UI is ON by default (W10); `RETRIBUTION_WEB_UI=0` or an explicit `web_ui: false` keeps Qt mode. Keep Qt screens working in Qt mode until WEB-09; in web mode stop using them. List in your PR what WEB-09 must delete.
- **Parallel work:** several agents run at once. Generated files (`client/openapi.json`, `client/src/api/_liberationApi.ts`) and `changelog.md` often conflict: on conflict, merge `origin/dev`, take dev's generated files and regenerate; never force-push.
- **API model titles must be unique** (`tests/server/test_openapi_titles.py`): two models with one title would share one generated client type.
- **Open your screen against a real game before reporting** when you can: `tests/flightplans/referencegame.py` builds one. Stop any dev server you start, and keep scratch files inside your own worktree.
